# Design: Fair Spin Core

## Architecture Decisions

### Decision: TypeScript + Vite, без UI-фреймворка

Код пише агент. Без системи типів немає автоматичного зворотного зв'язку — єдиною перевіркою лишаються очі людини в браузері. `tsc --noEmit` дає детермінований сигнал до відкриття сторінки.

Фреймворк не береться, бо застосунок — це три імперативні анімації над трьома плоскими структурами стану. Реактивний рендер у циклі анімації лише заважає.

Vite обрано замість статики без збірки саме через PWA: список файлів для офлайн-кешу генерується зі збірки автоматично. Список, який треба оновлювати руками при кожному новому файлі — рівно те, що агент забуває зробити.

### Decision: Фізика окремо від DOM

Симуляція — чиста функція над станом, без доступу до DOM і без таймерів. Це робить її юніт-тестованою, а вимогу детермінізму — перевірюваною в CI, а не на око.

### Decision: SVG для колеса, DOM для решти

Сектори — `<path>`, обертання — один `transform` на групі. Canvas не дає нічого, але додає ретина-масштабування, ручний хіт-тест і перемальовку тексту.

### Decision: Синтезований звук

Осцилятор із короткою обвідною замість аудіофайлів: нуль байтів у репозиторії та в офлайн-кеші, частота вільно прив'язується до швидкості. Контекст створюється при першому дотику, тому політика автовідтворення не заважає.

## Physics Model

Одновимірна модель, спільна для всіх столів. Колесо оперує кутом, котушка — зсувом; різниця лише в одиницях.

```
dω/dt = −μ − c·ω²
```

Стала складова `μ` обов'язкова: суто експоненційне згасання не зупиняється за скінченний час.

**Константи колеса** (початкові, підбираються на пристрої):

| Параметр | Значення | Наслідок |
|---|---|---|
| `μ` | 3.5 рад/с² | — |
| `ω₀` мінімум | 10.5 рад/с | 2.5 оберту, ≈3.0 с |
| `ω₀` стеля | 23 рад/с | ≈12 обертів, ≈6.6 с |
| `c` | мале | лише відчуття на високій швидкості |

Перевірка: шлях до зупинки `ω₀²/(2μ)`, час `ω₀/μ`.

**Крок інтегрування** — фіксований 1/120 с з акумулятором залишку. Рендер може йти будь-якою частотою; фізика — ні.

**Обчислення результату** виконується один раз, після того як `ω` впала нижче порога спокою: `index = floor(normalize(−angle + offset) / sectorAngle)`. До цього моменту переможця в стані немає.

## Gesture Pipeline

Pointer Events, один код для миші й пальця.

1. `pointerdown` → `setPointerCapture`, старт кільцевого буфера.
2. `pointermove` → запис `{ angle, timestamp }`, предмет іде за пальцем.
3. `pointerup` → швидкість = різниця по буферу за останні ≈100 мс.

Дві типові пастки: швидкість з останньої події дає нуль, якщо палець завмер перед відпусканням; без `touch-action: none` браузер перехоплює жест як скрол.

## Storage

Один ключ, JSON, обгортка над сховищем в одному модулі.

```ts
type Stored = {
  version: 1
  presets: Preset[]
  states: Record<PresetId, PresetState>
  settings: Settings
}
```

Запис дроселюється (≈300 мс). `migrate(raw): Stored` викликається на старті завжди, навіть коли версія поточна; на нерозпізнаних даних повертає чистий стан.

## Table Contract

Ядро не знає, що всередині столу.

```ts
interface Table {
  id: 'wheel' | 'reel' | 'cards'
  min: number
  max: number
  mount(el: HTMLElement, ctx: TableContext): void
  unmount(): void
}

interface TableContext {
  items: string[]              // лише ті, що лишились
  layout: LayoutState          // порядок і позиція, персистяться
  onResult(index: number): void  // рівно один раз, після зупинки
}
```

Нові столи додаються реалізацією цього інтерфейсу без правок логіки раунду.

## Deployment

`base: '/fair-spin/'` у конфігурації Vite. GitHub Actions на push у `main`: `typecheck` → `test` → `build` → публікація `dist/`.

Офлайн-режим — стратегія cache-first, реєстрація в межах підкаталогу, автоматичне оновлення кешу при новій збірці.

## Testing

Vitest, лише чиста логіка:

- фізика: мінімальний кидок дає ≥2.5 оберту; стеля обмежує; однакові вхідні дані дають однаковий результат; крок рендера не впливає на кінцеву позицію;
- сховище: міграція нерозпізнаних даних повертає чистий стан;
- раунд: вибуття, редагування пресету посеред раунду, фінальний акт.

DOM і анімації не тестуються.

## Known Platform Limits

Вібрація недоступна в Safari на iOS. Цільовий пристрій — Android, де вона працює повністю; на iPhone лишаються звук і візуальний відгук. Обхідних шляхів для вебзастосунку немає, тому це прийнято як обмеження, а не як задача.
