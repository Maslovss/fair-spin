# Proposal: Fair Spin Core

## Intent

Існуючі рандомайзери працюють однаково: `Math.random()` обирає переможця, зверху програється мальований ролик. Гравець натискає кнопку й дивиться відео, результат якого вже вирішено.

Fair Spin будується навпаки. Гравець хапає колесо за обід і робить ривок — сила ривка визначає, скільки обертів пройде колесо і де воно зупиниться. Результатом є те, куди воно доїхало. Застосунок не знає відповіді, доки предмет не зупинився.

Це не косметична різниця. Вона робить твердження «ти сам це накрутив» буквально правдивим і знімає вічне дитяче «та ти підкрутив».

## Scope

**In scope**

- Пресети: створення, редагування, видалення, стартовий набір із 7 штук.
- Раунд із вибуванням: цвинтар вибулих, продовження через дні, збереження позицій предметів.
- Стіл «Колесо»: жест-ривок, детермінована фізика, збереження кута між сесіями.
- Сховище в браузері з версіонованою схемою й міграціями.
- Локалізація uk/en, PWA з офлайн-роботою, звук, вібрація.
- Деплой на GitHub Pages.

**Out of scope** (окремі зміни після цієї)

- Столи «Котушка» (слот, стрічка) і «Карти» — `add-reel-table`, `add-cards-table`.

**Out of scope** (не входить у v1 взагалі — причини в `docs/mechanics.md` §8)

- Cooldown, сірі сектори вибулих, ваги окремим полем, undo кидка.
- Історія результатів, статистика, ачівки.
- Мультивибір однією дією, поділ на команди.
- Експорт/імпорт, шеринг через URL, реплей кидка.

## Approach

Ядро не знає, що всередині столу. Стіл отримує список і повідомляє індекс — один раз, після повної зупинки. Це дозволяє додавати нові столи наступними змінами, не чіпаючи логіку раунду.

Фізика — одна одновимірна модель на всі столи. Колесо оперує кутом, котушка зсувом; різниця лише в одиницях і в оформленні жесту.

Перша зміна дає працюючий застосунок на GitHub Pages з одним столом. Наступні дві додають столи по одному.
