# Design: Cards Table

## Decision: Чесність тут забезпечує порядок подій, а не фізика

На колесі й котушці гарантією є те, що результат неможливо знати до зупинки. На картах результат відомий у мить тапу — але не тому, що застосунок його обрав, а тому, що обрав гравець.

Ланцюг гарантій:

1. Тасування криптографічним генератором — застосунок не знає, чого хоче гравець.
2. Зріз гравцем — гравець власноруч завершує формування розкладки.
3. **Заморозка відповідності при роздачі** — далі жодних змін.
4. Вибір гравця серед однаково невідомих карт.

Ключовий пункт третій. Поки відповідність зафіксована до вибору, підкласти карту неможливо навіть теоретично.

## Note: Зріз не додає ентропії, і це не проблема

Математично зріз — це зсув колоди по колу, тож п'ять зрізів дають те саме, що один. Ентропія вже надана тасуванням.

Роль зрізу інша: це **обов'язкова дія гравця, яка запечатує розкладку**. Без неї порядок формує лише застосунок, і принцип «гравець діє перед результатом» тримається на чесному слові. Справжні гравці зрізають з тієї самої причини.

Тому вимога формулює зріз як обов'язковий, а не як опційну прикрасу.

## State Machine Reuse

Наявна машина станів приймає карти без змін:

| Стан | Колесо, котушка | Карти |
|---|---|---|
| `idle` | спокій | розкладка чекає вибору |
| `resolving` | фізика | **миттєвий**, результат відомий з тапу |
| `settling` | доводка до рамки | **анімація перевороту** |
| `revealing` | підсвітка, пауза | підсвітка, пауза |
| `applying` | вибуття, перебудова | політ у цвинтар або збирання колоди |

Це і є перевірка узагальнення ядра: стіл без фізики має пройти тим самим шляхом, лише з нульовим `resolving`.

Підготовчі дії — тасування, зріз, роздача — відбуваються у `idle` і станами не є. Ввід у них дозволений, бо результату вони не визначають.

## Layout

До 16 карт, сітка з адаптивною кількістю колонок. На телефоні орієнтир — 3 колонки для 9 карт, 4 для 12–16.

**Розкладка не перебудовується.** Взята карта лишає порожню комірку з ледь помітним контуром. Це і показ ходу раунду, і виконання вимоги «карти не рухаються після роздачі».

Позиції обчислюються один раз при роздачі й зберігаються. Перемальовка не має права їх переобчислювати.

## Cut Gesture

**Конвенція порядку.** `order[0]` — нижня карта колоди, `order[n-1]` — верхня.
У розтягнутому показі ліворуч лежить низ колоди, праворуч — верх.

**Геометрія.** Для зрізу стос розтягується по горизонталі так, щоб було видно
край кожної карти. Крок між картами обчислюється з доступної ширини й
кількості карт; для 16 карт край має лишатися достатнім, щоб у нього
можна було влучити пальцем.

**Жест.** Гравець веде пальцем упоперек розтягнутої колоди. Вертикальна
лінія-межа прилипає до проміжків між картами, а не рухається неперервно.
Відпускання виконує зріз. Альтернативний шлях — тап по карті: вона стає
новою нижньою.

**Обчислення.** Нехай `k` — індекс обраної карти в поточному порядку,
рахуючи від низу з нуля:

    cutOffset = (cutOffset + k) % n

Перевірка на прикладі: `[1..9]`, зріз по карті 5 → `k = 4` →
`[5,6,7,8,9,1,2,3,4]`. Обрана карта стала нижньою.

**Анімація.** Права частина піднімається, зсувається вліво й лягає під ліву;
ліва опускається зверху. Коротка, з пом'якшенням наприкінці. Після анімації
колода знову стос, готова до повторного зрізу або роздачі.

## State Shape

```ts
cards: {
  order: string[]      // після тасування
  cutOffset: number    // накопичений зріз
  cut: boolean         // чи був зріз у цьому циклі
  dealt: boolean
  positions: number[]  // фіксуються при роздачі
}
```

`positions` фіксують **де лежить кожна карта**, а не **що зараз на столі**.
Склад обчислюється при кожній перемальовці:

    visible = positions.filter(p => !drawn.includes(p.itemId))

Читати склад із `positions` без цієї звірки — і є той дефект, через який карти
показували вибулих після повернення з іншого столу.

При роздачі підсумкова відповідність = `rotate(order, cutOffset)`, і саме вона зберігається. Після цього `order` і `cutOffset` більше не використовуються до наступного тасування.

## Mode Change

Перемикання режиму змінює склад столу: при вимкненні вибування взяті карти повертаються. Продовжувати з розданою розкладкою неможливо, тому стіл повертається до нерозданого стану з новим тасуванням.

Це єдиний стіл із такою поведінкою — колесо й котушка просто перемальовуються.

## Sound

Синтезом, як і решта: шурхіт при тасуванні (короткий шум із швидким згасанням), сухий клац при зрізі, м'який ляск при перевороті. Аудіофайли не додаються.

## Testing

Чиста логіка, без DOM:

- зріз як зсув по колу, включно з переходом через межу;
- зріз `[1..9]` по карті 5 дає `[5,6,7,8,9,1,2,3,4]`;
- роздача недоступна без зрізу;
- відповідність, зафіксована при роздачі, не змінюється після взяття кількох карт;
- позиції не переобчислюються при перемальовці;
- режим без вибування вимагає нового зрізу після кожного перевороту;
- перемикання режиму повертає стіл до нерозданого стану;
- «Спробувати удачу» на нерозданій колоді виконує повну послідовність.
