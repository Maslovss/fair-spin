# Design: Question Templates

## Decision: Шаблон — стан, а не тип

Шаблон і завершене запитання є одним об'єктом у двох станах. Ознака обчислюється з назви й ніде не зберігається:

```ts
const SLOT = /…|\.\.\./
const isTemplate = (name: string) => SLOT.test(name)
const pose = (name: string, completion: string) =>
  name.replace(SLOT, completion)   // replace без /g — лише перше входження
```

Відсутність прапорця дає дві безкоштовні речі: користувач створює власні шаблони самою назвою, і імпортоване посилання поводиться правильно без додаткових полів.

Побічний ефект приймається свідомо: назва «Що робити… не знаю» стане шаблоном випадково. Нешкідливо — користувач бачить поле й перейменовує.

## Decision: Запитання живе в стані раунду

```ts
State(presetId): {
  lastTable
  elimination
  question?      // поставлене доповнення, лише для шаблонів
  drawn[]
  tables: {...}
}
```

Оскільки нове запитання неминуче означає новий раунд, окремого механізму скидання не з'являється: **«Нове запитання» і «Новий раунд» — одна дія з двома підписами**.

| Форма | Підпис | Видимість |
|---|---|---|
| Шаблон | Нове запитання | завжди |
| Завершене | Новий раунд | коли порядок непорожній |

Підтвердження — лише за непорожнього порядку, з наявним формулюванням «Скинути раунд? Вибуло 2 із 4».

## Decision: Порожнього запитання не існує

Підтвердження порожнього поля підставляє заглушку. Це знімає цілий стан «шаблон без запитання» після підтвердження й водночас поважає приватність: людина може не називати питання навіть застосунку.

Заглушка перекладається в момент підстановки й далі є вмістом. Реалізація: беремо `t('placeholder')` один раз при підтвердженні й записуємо результат у `question`. Не зберігати ключ — інакше при зміні мови поставлене запитання зміниться.

## Blocking

Єдина перевірка на вході в запуск розіграшу:

```ts
const canPlay = !isTemplate(preset.name) || state.question != null
```

Перевірка живе там само, де вже блокується ввід під час такту визнання. Окремих прапорців у столах не заводимо: шляхів запуску вже п'ять, і шостий забудуть.

Для карт блокування поширюється на зріз і роздачу, а не лише на вибір карти.

## UI

**Заголовок** показує поставлене запитання цілком. Доповнення візуально відрізняється від шаблонної частини — приглушений колір або кутові дужки, — щоб було видно, що саме вписано.

**Поле доповнення** відкривається тапом по заголовку. Порожнє, з підказкою сірим. Кнопка підтвердження доступна завжди, включно з порожнім полем.

**«Нове запитання»** — та сама дія, поруч із заголовком. Відкриває порожнє поле з курсором.

**«Зберегти як окреме запитання»** — у меню поруч із заголовком, лише на заповненому шаблоні без заглушки. Назва підставляється готовою.

**Скасування** у полі доповнення повертає до списку запитань: розіграш не починався, отже нічого й не почалось.

## Name Uniqueness

Перевірка при створенні, перейменуванні, збереженні копії та імпорті. Порівняння після обрізання пробілів.

Наслідок для імпорту: варіант «додати окремо» стає неможливим, у конфлікті лишаються заміна або скасування. Це враховано в `add-sharing`.

## Migration

Схема піднімається до версії 3.

Старий стартовий набір **не чіпається**: він є даними користувача. Нові запитання не додаються автоматично — для цього є дія в налаштуваннях.

Поле `question` необов'язкове, отже наявні стани валідні без міграції даних. Міграція лише піднімає номер версії.

## Testing

- розпізнавання трикрапки в обох написаннях;
- підстановка лише в першу трикрапку;
- заглушка заморожується після підстановки;
- нове запитання очищує порядок, перемішує розкладки, робить колоду нерозданою;
- блокування всіх шляхів запуску, включно з «Спробувати удачу» та діями карт;
- унікальність назв у чотирьох сценаріях;
- копія шаблону незалежна від оригіналу;
- «Додати стартові запитання» пропускає наявні назви й не чіпає раунди.
