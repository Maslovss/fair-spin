# Delta for Presets

## ADDED Requirements

### Requirement: Template Affordance In The Editor

Редактор запитання SHALL робити конвенцію шаблона очевидною без документації.

Під полем назви MUST показуватись живий попередній перегляд, що змінюється під час набору й повідомляє, яку форму дає поточний текст:

- назва **без** трикрапки — повідомлення, що це готове запитання, яке можна крутити одразу;
- назва **з** трикрапкою — повідомлення, що це шаблон, разом із показом самого запитання, де на місці трикрапки стоїть позначка місця для тексту користувача.

Перегляд MUST оновлюватися при кожній зміні назви, а не лише при збереженні.

#### Scenario: Preview for a ready question

- GIVEN користувач вводить назву «Вечеря у п'ятницю»
- WHEN він дивиться під поле назви
- THEN повідомлено, що це готове запитання

#### Scenario: Preview for a template

- GIVEN користувач вводить назву «Коли…?»
- WHEN він дивиться під поле назви
- THEN повідомлено, що це шаблон
- AND показано запитання з позначкою місця для тексту користувача

#### Scenario: Preview updates while typing

- GIVEN у полі назви «Коли»
- WHEN користувач дописує трикрапку
- THEN перегляд одразу змінюється з готового запитання на шаблон

#### Scenario: Three dots are recognised too

- GIVEN користувач вводить «Коли...?»
- WHEN він дивиться на перегляд
- THEN повідомлено, що це шаблон

### Requirement: Turning A Name Into A Template

Коли назва не містить трикрапки, редактор SHALL пропонувати явну дію, що перетворює її на шаблон додаванням трикрапки.

Трикрапка MUST вставлятися в позицію курсора, а коли поле не у фокусі — перед знаком питання в кінці назви, якщо він є, інакше в кінець.

Дія MUST NOT з'являтися, коли назва вже містить трикрапку.

Дія MUST змінювати лише текст назви й MUST NOT створювати окремого поля чи ознаки в даних.

#### Scenario: Making a template

- GIVEN у полі назви «Хто миє посуд?» і поле не у фокусі
- WHEN користувач виконує дію
- THEN назва стає «Хто миє посуд…?»
- AND перегляд повідомляє, що це шаблон

#### Scenario: Inserting at the cursor

- GIVEN у полі назви «Що подарувати мамі?» і курсор після слова «подарувати»
- WHEN користувач виконує дію
- THEN трикрапку вставлено в позицію курсора

#### Scenario: Action is hidden for templates

- GIVEN назва вже містить трикрапку
- WHEN користувач переглядає редактор
- THEN дії перетворення немає

### Requirement: Editor Hints Show Both Forms

Підказка поля назви MUST демонструвати форму шаблона прикладом, а не лише готове запитання. Наявна підказка поля елементів про повтори як ваги MUST зберігатися.

#### Scenario: Name placeholder teaches the template form

- GIVEN користувач відкриває редактор із порожньою назвою
- WHEN він дивиться на поле назви
- THEN приклад у підказці містить трикрапку

### Requirement: Inline Question Composition

Під час постановки запитання поле вводу MUST розташовуватись **на місці трикрапки всередині самого запитання**, а не окремо від нього. Незмінні частини назви до та після місця підстановки MUST лишатися видимими як текст.

Запитання MUST читатися цілком під час набору, включно з текстом після місця підстановки.

Поле MUST зростати за вмістом, а запитання MUST переноситися рядками природно, як звичайний текст. Довге доповнення MUST NOT обрізатися й MUST NOT ховати решту запитання.

Поки поле порожнє, у ньому MUST показуватись приглушеним текстом **та сама заглушка**, яка підставиться при підтвердженні порожнього поля. Окремої позначки місця з іншим текстом MUST NOT існувати: користувач бачить рівно те, що отримає.

#### Scenario: Field sits inside the question

- GIVEN шаблон «Коли…?»
- WHEN користувач ставить запитання
- THEN слово «Коли» видно ліворуч від поля
- AND знак питання видно праворуч від поля

#### Scenario: Text after the slot stays visible

- GIVEN шаблон «Що подарувати… на день народження?»
- WHEN користувач вводить доповнення
- THEN текст «на день народження?» лишається видимим праворуч від поля

#### Scenario: Long completion wraps

- GIVEN шаблон із текстом після місця підстановки
- WHEN користувач вводить довге доповнення
- THEN запитання переноситься рядками
- AND жодна частина запитання не прихована

#### Scenario: Empty field shows the actual placeholder

- GIVEN поле доповнення порожнє
- WHEN користувач дивиться на запитання
- THEN у полі приглушеним текстом показано ту саму заглушку, яка підставиться при порожньому підтвердженні
- AND окремої позначки місця з іншим текстом немає

#### Scenario: Dialog has no separate title

- GIVEN відкрито постановку запитання
- WHEN користувач дивиться на діалог
- THEN заголовком є саме запитання з полем усередині
- AND окремої назви діалогу немає
- AND підпису поля немає

### Requirement: Posed Question Is Not Directly Editable

Після постановки запитання заголовок MUST бути звичайним текстом. Дотик до нього MUST NOT відкривати поле вводу.

Змінити запитання можна лише явною дією постановки нового запитання, оскільки будь-яка зміна означає новий раунд і втрату порядку.

#### Scenario: Tapping a posed question does nothing

- GIVEN поставлено запитання «Коли поїхати до бабусі?»
- WHEN користувач торкається заголовка
- THEN поле вводу не відкривається
- AND раунд не змінюється

#### Scenario: Changing requires the explicit action

- GIVEN поставлено запитання
- WHEN користувач обирає постановку нового запитання
- THEN поле вводу відкривається порожнім
- AND діють наявні правила підтвердження та скидання раунду
