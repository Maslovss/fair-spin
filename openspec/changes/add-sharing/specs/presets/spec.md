# Delta for Presets

## ADDED Requirements

### Requirement: Question Sharing Link

Користувач SHALL мати змогу отримати посилання на запитання. Посилання MUST містити лише назву та елементи.

Стан гри — обраний стіл, режим вибування, поставлене запитання, порядок — MUST NOT потрапляти в посилання. Дані MUST розміщуватись у хеші адреси, який не надсилається на сервер. Створення посилання MUST NOT виконувати жодного мережевого запиту.

Посилання MUST містити позначку версії формату, щоб посилання майбутніх версій можна було відхилити, не розбираючи вміст.

#### Scenario: Sharing a question

- GIVEN користувач відкрив запитання
- WHEN він обирає поділитися ним
- THEN отримано посилання на застосунок із даними в хеші
- AND мережевих запитів не виконувалось

#### Scenario: Personal state stays behind

- GIVEN шаблон із поставленим запитанням, незавершеним раундом і обраним столом «Карти»
- WHEN створюється посилання
- THEN у ньому лише назва та елементи
- AND поставленого запитання, порядку, режиму й столу в ньому немає

#### Scenario: Templates travel as templates

- GIVEN користувач ділиться шаблоном «Хто…?»
- WHEN отримувач додає його
- THEN назва містить трикрапку
- AND у отримувача воно поводиться як шаблон

#### Scenario: Completed questions travel as they are

- GIVEN користувач ділиться запитанням «Хто викидає сміття?»
- WHEN отримувач додає його
- THEN трикрапки в назві немає
- AND розіграш доступний одразу

#### Scenario: Unknown format version

- GIVEN відкрито посилання з невідомою позначкою версії
- WHEN застосунок його розбирає
- THEN показано, що посилання створене новішою версією
- AND нічого не додається

### Requirement: Long List Falls Back To Text

Коли посилання перевищує допустиму довжину, застосунок SHALL натомість запропонувати поділитися списком звичайним текстом, по одному елементу на рядок.

Окремого механізму імпорту для цього випадку не потрібно: редактор запитання вже розбирає багаторядкову вставку.

#### Scenario: List too long for a link

- GIVEN запитання з 800 елементами
- WHEN користувач обирає поділитися ним
- THEN замість посилання пропонується текстовий список
- AND пояснено, що список завеликий для посилання

#### Scenario: Receiving a text list

- GIVEN отримувач має текстовий список
- WHEN він вставляє його в поле елементів нового запитання
- THEN кожен рядок стає окремим елементом

### Requirement: Import Is Untrusted Input

Дані з посилання MUST вважатися недовіреними. Застосунок MUST перевіряти кількість елементів, довжину кожного елемента та довжину назви за тими самими межами, що діють у редакторі, і MUST відкидати керуючі символи.

Імпорт MUST NOT відбуватися автоматично. Користувач MUST побачити назву та кількість елементів і підтвердити дію.

Після рішення користувача хеш MUST очищатися, щоб оновлення сторінки не повторювало імпорт.

#### Scenario: Preview before adding

- GIVEN користувач відкрив посилання на запитання
- WHEN застосунок розібрав дані
- THEN показано назву та кількість елементів
- AND нічого не додано, доки користувач не підтвердив

#### Scenario: Oversized payload is rejected

- GIVEN посилання містить більше елементів, ніж дозволено
- WHEN застосунок його розбирає
- THEN імпорт відхилено з поясненням
- AND сховище не змінено

#### Scenario: Malformed payload is rejected

- GIVEN посилання пошкоджене або не розбирається
- WHEN застосунок його відкриває
- THEN показано, що посилання непридатне
- AND застосунок працює далі у звичайному режимі

#### Scenario: Hash is cleared after the decision

- GIVEN користувач підтвердив або скасував імпорт
- WHEN він оновлює сторінку
- THEN імпорт не пропонується повторно

### Requirement: Identical Question Is Not Duplicated

Коли запитання з такою самою назвою вже існує й його елементи повністю збігаються з отриманими, застосунок SHALL повідомити, що таке запитання вже є, і NOT MUST створювати копію чи пропонувати вибір.

#### Scenario: Nothing to do

- GIVEN у користувача є запитання «Хто…?» із тими самими елементами
- WHEN він відкриває посилання на таке саме «Хто…?»
- THEN показано, що таке запитання вже є
- AND копії не створено
- AND вибору не пропонується

### Requirement: Import Conflict Resolution

Коли запитання з такою самою назвою існує, але елементи відрізняються, застосунок MUST запитати рішення й MUST NOT об'єднувати списки автоматично.

Показується **різниця**, а не два списки: скільки елементів додається, скільки зникає, і які саме.

Оскільки назви унікальні, додати копію поруч неможливо. Доступні дії: **замінити наявне** або **скасувати**. Типово обрано скасування як безпечну дію.

Заміна MUST попереджати, що незавершений раунд наявного запитання буде скинуто, оскільки склад списку змінюється.

Користувачеві MUST бути пояснено, що для збереження обох списків потрібно спершу перейменувати наявне запитання.

#### Scenario: Conflict shows a difference

- GIVEN у користувача є запитання «Хто…?» із восьми елементів
- WHEN він відкриває посилання на «Хто…?» із дев'яти інших елементів
- THEN показано, скільки елементів додається та скільки зникає
- AND два повні списки поруч не показуються

#### Scenario: Only replace or cancel

- GIVEN показано конфлікт
- WHEN користувач переглядає доступні дії
- THEN пропонується замінити або скасувати
- AND додавання копії поруч не пропонується
- AND пояснено, що для збереження обох треба перейменувати наявне

#### Scenario: Replacing warns about the round

- GIVEN наявне запитання має незавершений раунд
- WHEN користувач обирає замінити
- THEN попереджено, що раунд буде скинуто
- AND лише після підтвердження список замінено й раунд скинуто

#### Scenario: Cancelling changes nothing

- GIVEN показано конфлікт
- WHEN користувач скасовує
- THEN сховище не змінено

#### Scenario: Lists are never merged

- GIVEN показано конфлікт
- WHEN користувач переглядає доступні дії
- THEN об'єднання списків не пропонується
