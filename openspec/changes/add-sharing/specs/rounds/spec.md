# Delta for Rounds

## ADDED Requirements

### Requirement: Sharing The Result

Користувач SHALL мати змогу поділитися результатом розіграшу. Використовується системний лист поширення, а за його відсутності — копіювання в буфер обміну.

Зміст залежить від режиму: при вимкненому вибуванні передається результат останньої дії, при увімкненому — порядок.

Заголовком тексту MUST бути **поставлене запитання**, а не назва зі списку. Для шаблона це означає назву з підставленим доповненням, включно із заглушкою.

Поширення MUST NOT виконувати мережевих запитів.

#### Scenario: Sharing a single result

- GIVEN вибування вимкнено й отримано результат
- WHEN користувач ділиться ним
- THEN текст містить поставлене запитання, назву столу та результат

#### Scenario: Template header is the posed question

- GIVEN шаблон «Коли…?» доповнено текстом «поїхати до бабусі»
- WHEN користувач ділиться результатом
- THEN заголовком тексту є «Коли поїхати до бабусі?»
- AND назва «Коли…?» у тексті не з'являється

#### Scenario: Placeholder is shared as is

- GIVEN поставлено запитання із заглушкою
- WHEN користувач ділиться результатом
- THEN заголовком є запитання із заглушкою
- AND підстановки іншого тексту не відбувається

#### Scenario: Sharing an order

- GIVEN вибування увімкнено й у порядку є записи
- WHEN користувач ділиться
- THEN текст містить назву пресету та пронумерований порядок

#### Scenario: No share sheet available

- GIVEN системний лист поширення недоступний
- WHEN користувач ділиться
- THEN текст скопійовано в буфер обміну
- AND про це повідомлено

### Requirement: Shared Text Does Not Evaluate The Outcome

Текст повідомлення MUST бути нейтральним. Застосунок не знає, чи випасти першим добре: «хто ходить першим» і «хто миє посуд» влаштовані однаково.

Заборонені формулювання:

- оцінювальні слова: «вибули», «переможець», «пощастило», «на жаль»;
- дієслова минулого часу, оскільки стать того, хто крутив, і рід елемента невідомі;
- твердження, що вибір зроблено застосунком, оскільки чесність переказу він гарантувати не може.

Використовується та сама назва, що й в інтерфейсі: **Порядок**. Внутрішні робочі назви в текстах і ключах локалізації не з'являються.

#### Scenario: Neutral wording

- GIVEN формується текст повідомлення
- WHEN у порядку є записи
- THEN використано слово «Порядок»
- AND слова «вибули» чи «переможець» відсутні

#### Scenario: No claim of authorship

- GIVEN формується текст повідомлення
- WHEN згадується результат
- THEN не стверджується, що вибір зробив застосунок

### Requirement: Shared Order Shows Completeness

Текст порядку MUST розрізняти завершений і незавершений раунд числами, а не словами з оцінкою.

Завершений раунд позначається загальною кількістю, незавершений — кількістю записів із загальної кількості елементів.

#### Scenario: Completed round

- GIVEN раунд завершено й у порядку три записи
- WHEN формується текст
- THEN позначено, що це всі три

#### Scenario: Round in progress

- GIVEN у порядку три записи з дванадцяти елементів
- WHEN формується текст
- THEN позначено три з дванадцяти

### Requirement: Long Order Is Truncated Honestly

Коли порядок задовгий для повідомлення, він SHALL обрізатися з явною позначкою, скільки записів не показано. Повний порядок лишається доступним через копіювання, яке обрізання не застосовує.

#### Scenario: Truncated order

- GIVEN у порядку 60 записів із 81 елемента
- WHEN формується текст повідомлення
- THEN показано початок порядку
- AND явно позначено, скільки записів не показано

#### Scenario: Copying is not truncated

- GIVEN той самий порядок
- WHEN користувач копіює порядок
- THEN скопійовано всі записи

### Requirement: Result Message Carries No List Link

Повідомлення про результат MUST NOT містити посилання на список. Отримувач, який крутне за таким посиланням, отримає інший результат, і це створило б враження перевірки там, де її немає.

Поділитися списком лишається окремою дією.

#### Scenario: No verification illusion

- GIVEN користувач ділиться результатом
- WHEN формується текст
- THEN посилання на пресет у ньому немає
